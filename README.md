# AQYL — AI-репетитор для каждой школы Казахстана

**Future Minds Hackathon 2026 · Трек 2 — Social Impact Challenge**

> Как искусственный интеллект может помочь ученикам Казахстана получать качественное
> персонализированное образование независимо от того, где они живут?

AQYL (қаз. *ақыл* — «разум») — адаптивная платформа, которая находит **настоящую причину**
пробела в знаниях школьника, а не его симптом, строит персональный план подготовки под дату
экзамена и полностью работает **без интернета**.

---

## Запуск за 30 секунд

```bash
node server.js
```

Затем откройте <http://localhost:4173>.

Сборка не нужна: ни одной зависимости, ни одного шага компиляции. Локальный сервер требуется
только потому, что ES-модули не грузятся по протоколу `file://`. Для продакшена достаточно
залить каталог как есть на Vercel, Netlify или GitHub Pages.

Питч-дек: откройте `pitch/index.html` и напечатайте в PDF (A4 альбомная, поля «нет»,
фоновая графика включена).

## Что делает продукт

| Экран | Что происходит |
|---|---|
| **Главная** | Ценностное предложение, сравнение с типичными платформами, объяснение подхода |
| **Профиль** | Класс, предметы, цель обучения, регион, дата экзамена |
| **Диагностика** | 8 адаптивных вопросов: следующий выбирается там, где ответ даёт максимум информации |
| **Кабинет** | Уровень θ, карта освоения, слабые места, рекомендации **с указанием причин и весов** |
| **Карта знаний** | Интерактивный граф: размер узла — освоение, цвет — статус, замок — не хватает базы |
| **Практика** | Задание в зоне ближайшего развития, лестница из 3 подсказок, разбор ошибки, озвучка |
| **План** | Недельный роадмап до экзамена + честный ответ «успеваешь / нужно N ч в неделю» |
| **AI-репетитор** | Сократовский диалог: ведёт вопросами, готовый ответ не выдаёт |
| **Панель учителя** | Тепловая карта класса, ученики в зоне риска, приоритет тем, добавление модулей |

Всё это работает на трёх языках — **қазақша, русский, English** — включая тексты заданий,
подсказок и разборов (казахский и русский), а не только подписи кнопок.

## Как устроен ИИ

Мы сознательно не использовали «чёрный ящик». Все три модели дают числа, которые можно
показать ученику, объяснить учителю и проверить на защите.

### 1. Bayesian Knowledge Tracing — `src/engine/mastery.js`

Вероятность `P(тема освоена)` обновляется по формуле Байеса после каждой попытки с учётом того,
что ученик мог **угадать** (`p_guess = 0.22`) или **ошибиться по невнимательности** (`p_slip = 0.10`),
плюс вероятность выучить тему в момент решения (`p_transit = 0.18`).
Дополнительно применяется **кривая забывания Эббингауза**: без повторения уверенность падает
экспоненциально (период полураспада — 14 дней), а интервалы повторения назначаются по
упрощённому SM-2.

### 2. Elo-рейтинг и IRT — `src/engine/mastery.js`, `src/engine/recommender.js`

Способность ученика `θ` и сложность задания `b` живут в одной логит-шкале. После каждого ответа
θ обновляется с K-фактором, убывающим по мере накопления опыта. Задание подбирается так, чтобы
предсказанная вероятность успеха была ≈ 70 % — **зона ближайшего развития по Выготскому**.
В диагностике цель другая: вопрос выбирается ближе к 50 %, потому что именно там ответ несёт
максимум информации об ученике.

### 3. Вывод по графу знаний — `src/engine/recommender.js` ⭐

Ключевое отличие продукта. Темы связаны рёбрами «нельзя понять X без Y».

- **Поиск первопричины.** От слабой темы система спускается вниз по рёбрам и находит настоящий
  источник ошибок. Спуск происходит только если предпосылка действительно слабая **и не сильнее
  самой темы** — иначе система «проваливалась» бы до корня графа всегда. Приоритет отдаётся
  предпосылкам, по которым есть реальные ответы ученика.
- **Оценка непройденных тем.** Не ставится «по умолчанию 25 %». Берётся априор из θ и b,
  затем накладываются ограничения: **потолок** — тема не может быть освоена заметно лучше своей
  слабейшей предпосылки; **пол** — если следствие темы освоено, значит и сама тема фактически
  освоена. Поэтому в интерфейсе такие темы честно помечены как «оценка по графу».
- **Объяснимость.** Приоритет темы складывается из слагаемых (пробел, готовность базы, связь с
  целью, ценность разблокировки, срок повторения), и **все они показаны пользователю с весами**.

### 4. Репетитор — `src/engine/tutor.js`

Два режима, переключаются в интерфейсе:

- **Офлайн (по умолчанию).** Вопрос токенизируется и ранжируется по учебному графу (частотное
  взвешивание, устойчивое к словоформам), ответ собирается педагогической политикой: определяется
  намерение, подтягивается карта пробелов ученика, выбирается следующий шаг. Ноль сети, ноль
  стоимости, задержка в миллисекундах.
- **Cloud.** Тот же собранный контекст уходит в **Claude API** одним запросом с системным
  промптом, запрещающим выдавать готовый ответ. Ключ хранится только в localStorage браузера.

Главное правило политики в обоих режимах: **готовый ответ не выдаётся**. На просьбу «подскажи
ответ» репетитор возвращает следующую ступень лестницы подсказок — встречный вопрос.

## Архитектура

```
index.html              оболочка, шапка, футер
manifest.webmanifest    PWA
sw.js                   service worker: network-first с откатом в кэш
server.js               локальный статический сервер (только для разработки)
styles/
  tokens.css            дизайн-токены, тёмная и светлая темы
  app.css               компоненты и адаптив
src/
  main.js               хеш-роутер, оболочка, глобальные действия
  state.js              хранилище, localStorage, XP, стрики, достижения
  i18n.js               kk / ru / en
  data/
    curriculum.js       граф знаний: 14 тем, 42 задания с подсказками и разборами
    seed.js             детерминированный класс из 20 учеников для панели учителя
  engine/
    mastery.js          BKT, Elo, забывание, интервальное повторение
    recommender.js      вывод по графу, поиск первопричины, подбор заданий
    planner.js          топологическая сортировка, роадмап под дату экзамена
    tutor.js            сократовская политика, поиск по графу, мост в Claude API
  ui/                   dom.js + по модулю на экран
pitch/index.html        питч-дек на 12 слайдов, печатается в PDF
```

**Почему без фреймворка.** Это не эстетическое предпочтение, а следствие задачи: приложение
должно открываться на школьном ноутбуке и мобильном интернете сельской школы. Ноль зависимостей
означает мгновенную загрузку, отсутствие шага сборки, который может сломаться на защите, и
возможность объяснить жюри любую строку кода.

## Данные: что реально, а что демо

| Данные | Статус |
|---|---|
| Прогресс ученика, θ, карта освоения, XP, достижения | **Реальные вычисления** на ответах пользователя |
| Граф знаний, 42 задания, подсказки, разборы, типичные ошибки | Написаны вручную под программу РК, 7–11 классы |
| Класс из 20 учеников в панели учителя | **Демо-данные**: детерминированный PRNG с фиксированным зерном — картина стабильна при демонстрации, но статистически правдоподобна |
| Статистика на главной (PISA, доля семей) | Оценки по публичным данным Бюро нацстатистики РК и OECD; уточняются в питче |
| Хранилище | localStorage по схеме будущей БД (users, mastery, attempts, classes) |

## Доступность

- Три языка, включая содержание заданий на казахском
- Синтез речи (Web Speech API) для учеников с дислексией и слабым зрением
- Светлая тема для школьных проекторов и дневных классов
- Полная навигация с клавиатуры, `:focus-visible`, skip-link, ARIA-подписи
- Поддержка `prefers-reduced-motion`
- Mobile-first вёрстка: проверено от 375 px

## Использование ИИ при разработке

Код написан в паре с ИИ-ассистентом (Claude). Ассистент использовался для генерации шаблонного
кода интерфейса, вёрстки и части учебного контента. Архитектура, выбор и настройка моделей
(BKT, Elo/IRT, логика вывода по графу и поиска первопричины), педагогическая политика репетитора
и структура учебного графа — решения команды; каждая формула в `src/engine/` прокомментирована
и защищается на Q&A.
